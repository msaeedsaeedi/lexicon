# Lexicon v0.3.0 — Dataset Health

v0.3.0 makes the checksum-locked OEWN 2025 dataset measurable and regression-safe. It publishes
dataset and pipeline version `0.3.0` while retaining canonical schema version `0.2.0`.

## Health report and baseline

Every build writes `health-report.json` and records it in `manifest.json` and
`release-manifest.json`. The report records independent counts for lexemes, forms, senses,
definitions, and examples; part-of-speech coverage; example and gloss coverage; missing source
provenance; required source-sense-key coverage; and exact duplicate staging inputs.

`data/quality/oewn-2025.baseline.json` pins the expected report for the OEWN 2025 source ID,
version, and SHA-256. A build may use `--baseline PATH` to require an exact match. Any changed
source identity or metric fails with `quality.regression`; the release workflow always supplies
this baseline. Seed builds still emit a health report without requiring the OEWN baseline.

## Artifact agreement

`lexicon validate` accepts either one SQLite/JSONL artifact or a build directory. Directory
validation checks both canonical artifacts and fails if their record counts differ. Release
verification requires matching artifacts, the health report, attribution, and checksum-valid
manifests before publishing `dist/lexicon-en-oewn-0.3.0`.

The release does not add lexical sources, semantic relations, frequency, pronunciation,
morphology, learner state, or CI. OEWN coverage limitations, including senses without examples,
are reported as source-quality metrics rather than treated as release failures.
