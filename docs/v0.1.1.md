# Lexicon v0.1.1 hardening contract

v0.1.1 keeps the v0.1.0 canonical schema and dataset version. It advances the pipeline version
to `0.1.1` and strengthens the build contract.

## Build safety

- Builds validate source license and URL metadata, source references, canonical forms, and
  artifact metadata before reporting success.
- Exact duplicate staging records are discarded deterministically and listed in
  `duplicate-report.json`.
- Records that normalize to the same lexeme ID but disagree fail the build; they are never merged.
- Expected pipeline failures use a stable diagnostic category such as
  `normalization.invalid_record` or `overrides.invalid_configuration`.

## Overrides

The default override directory is `data/overrides/`. It must contain both files:

```text
blocked-lexemes.json
definition-fixes.json
```

`blocked-lexemes.json` contains `{ "lexeme_id", "reason" }` entries. `definition-fixes.json`
contains `{ "definition_id", "text" }` entries. Every referenced ID must exist in the
normalized dataset. Overrides are applied after normalization and before validation and artifact
compilation, so raw source data remains unchanged and auditable.

See `docs/overrides.md` for the full behaviour, formats, error cases, and examples.
