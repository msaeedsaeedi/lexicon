# Lexicon v0.4.0 — Automated Dataset Publishing

v0.4.0 is the publishing and release-automation milestone. It keeps the v0.2.0 canonical schema and
the existing SQLite/JSONL artifact contract unchanged, and makes the verified release bundle a
distributable, immutable GitHub Release artifact.

## Unchanged dataset contract

Schema version remains `0.2.0`. Dataset and pipeline versions are `0.4.0`. No data-model changes,
readiness scoring, or consumer-selection hints are added. The consumer contract in
[`docs/consumer-contract.md`](consumer-contract.md) and the SQLite query surface are unchanged.

Vocab compatibility range and the Vocab migration path are intentionally not modified in this
release. `vocab-compat-0.4.0.json` remains in the bundle as a **deprecated migration aid**: it is
the temporary `{word, definition, example}` projection only, and SQLite remains the preferred
runtime artifact.

## OEWN baseline requirement

Every release build runs against the checksum-locked OEWN 2025 archive in
`data/sources/oewn-2025.lock.json` and requires the fresh `health-report.json` to match
`data/quality/oewn-2025.baseline.json` exactly. Any source-identity or metric change fails with
`quality.regression` and blocks the release.

## Release contents

A v0.4.0 release publishes three artifacts per tag:

```text
dist/lexicon-en-oewn-0.4.0/            # verified release bundle directory
dist/lexicon-en-oewn-0.4.0.tar.gz      # deterministic archive of the bundle
dist/lexicon-en-oewn-0.4.0.tar.gz.sha256  # top-level SHA-256 checksum of the archive
```

The bundle directory contains the canonical artifacts, manifests, reports, attribution, and the
legacy compatibility export exactly as in v0.3. The `.tar.gz` archive is deterministic: it uses a
fixed entry timestamp, normalized ownership and modes, sorted entries, and a fixed gzip header
timestamp, so rebuilding the same bundle produces byte-identical archives. Extracting it yields the
exact `lexicon-en-oewn-0.4.0/` bundle directory, and its included `release-manifest.json` and
checksums are re-verified during archive verification.

## Release gate and verification steps

The GitHub Actions workflow in `.github/workflows/release.yml` runs only on pushes of `v*` tags and
enforces, in order:

1. The tag equals `v<DATASET_VERSION>` (that is, `v0.4.0`).
2. The tag points exactly to the current `main` commit.
3. No GitHub Release already exists for the tag (releases are immutable; assets are never replaced).
4. `scripts/release.py` runs the full preflight: formatting, Ruff, Pyright, pytest, OEWN
   acquisition and checksum check, OEWN import, baseline regression check, artifact validation,
   manifest generation, and release verification.
5. The deterministic archive and its top-level checksum are created from the verified bundle.
6. The archive is verified by re-checking its SHA-256 and re-validating the extracted bundle,
   including `release-manifest.json`.
7. The archive and checksum are attached to a new GitHub Release with autogenerated notes.

Third-party workflow actions are pinned by commit SHA.

## Developer workflow

```bash
uv sync
uv run python scripts/release.py          # local preflight; builds and verifies the full release
```

`scripts/release.py` is the single source of release assembly and verification; the GitHub Actions
workflow invokes exactly this script before publishing. The local command builds a fresh bundle
under `dist/lexicon-en-oewn-0.4.0`, then creates and verifies `dist/lexicon-en-oewn-0.4.0.tar.gz`
and its checksum. It fails rather than overwriting an existing release.

To publish, merge the versioned release commit to `main`, optionally run the local preflight, then
create and push the annotated tag:

```bash
git tag -a v0.4.0 -m "v0.4.0"
git push origin v0.4.0
```

The workflow publishes only after validating that exact tag and commit.
